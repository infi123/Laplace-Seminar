# סמינר התמרת לפלס — מערכת בנייה אוטומטית

זהו **הפרויקט שלך מ־Overleaf**, עם קוד Beamer המקורי, 33 שקפים, תיקיית `assets`, הערות מרצה, קוד Manim קיים ומערכת בנייה חדשה. שמרנו על ההרצאה ללא פרק PDE.

## מה המערכת עושה?

בעת הפעלת `python build_all.py`:

1. מקמפלת את `main.tex` ב־XeLaTeX (בדיוק כמו Overleaf).
2. מוודאת שמספר העמודים ב־PDF תואם למספר השקפים (וכך אין הזזה שקטה של הסרטונים).
3. מייצרת תמונה לכל שקף מתוך ה־PDF.
4. מייצרת מחדש רק סרטוני MP4 שהקוד/הכותרת/ההגדרות שלהם השתנו (אחרים נשמרים ב־cache).
5. מכינה מצגת HTML עצמאית, שאפשר להוריד כקובץ אחד ולפתוח גם ללא אינטרנט. הסרטונים מתנגנים **בתוך השקף עצמו**, ולא בחלונות קופצים.
6. מכינה גם תיקיית נגן קלילה וקובץ PDF לגיבוי.

הכל מסודר בתוך `dist/`:

| קובץ | מה הוא עושה |
|---|---|
| `dist/index.html` | **גרסת ההצגה המומלצת** — קובץ HTML עצמאי הכולל את כל התמונות והסרטונים |
| `dist/presentation.pdf` | PDF עדכני לגיבוי והדפסה |
| `dist/viewer/index.html` | נגן HTML קל שמשתמש בקבצים שבתיקיות הסמוכות |
| `dist/viewer/videos/` | קובצי MP4 עם **המקראים והכיתובים בתוך הווידאו עצמו** |
| `dist/viewer/slides/` | תמונות השקפים |

## הפעלה במחשב

דרישות: Python 3.11+, XeLaTeX/`latexmk`, `ffmpeg` וחבילות Python מ־`requirements.txt`.

```bash
python -m pip install -r requirements.txt
python build_all.py
```

לאחר מכן פתחו ב־Chrome או Edge את `dist/index.html`. לחצו `F` למסך מלא; חץ שמאלה או רווח לשקף הבא. אם הדפדפן חוסם ניגון אוטומטי, לחצו על כפתור ההפעלה.

**פקודות שימושיות:**

```bash
python build_all.py                # בנייה רגילה עם מטמון
python build_all.py --clean        # בנייה נקייה לחלוטין
python build_all.py --force-videos # רינדור מחדש של כל האנימציות
python -m unittest discover -s tests -v
```

`build_offline_viewer.py` הישן הוחלף בעטיפה של המערכת החדשה, כדי שלא יחזור הנגן התקול עם חלונות קופצים.

## איך עורכים שקפים והמחשות?

- **נוסחאות, שקפים והסברים**: משנים `main.tex`.
- **תמונות סטטיות**: מעדכנים את `assets/`.
- **המתמטיקה, הצירים והמקראים של הסרטונים המובנים**: משנים `tools/native_animations.py`.
- **אורך/קצב הסרטונים והמנוע לכל סרטון**: משנים `animations_config.json`.
- **סצנות Manim נוספות**: נמצאות ב־`manim/laplace_scenes.py`.

ההמחשות שממופות אוטומטית כרגע:

| מזהה | מספר שקף נוכחי | תוכן |
|---|---:|---|
| `euler_decay` | 6 | מעגל אוילר ותנודה דועכת יחד |
| `complex_modes` | 8 | מישור מרוכב ומצבים אקספוננציאליים |
| `time_shift` | 21 | אות מושהה בזמן, עם מקרא וחץ |
| `dirac_pulse` | 23 | פולס שטחו 1 ורוחבו מצטמצם |
| `convolution` | 27 | שני פולסים, שטח חפיפה וערך הקונבולוציה |
| `system_response` | 29 | קלט, תגובת אימפולס ופלט |

המיפוי נעשה באמצעות הערה ייחודית **מיד לפני שקף ההמחשה** בקובץ `main.tex`:

```tex
% ANIM: convolution
\visualframe{המחשה: קונבולוציה כשטח חפיפה}{11_convolution.png}{...}
```

אם תוסיף שקפים לפני האנימציה, המערכת תזהה את המיקום החדש אוטומטית. כשמוסיפים **המחשה חדשה**, יש להוסיף מזהה ל־`animations_config.json`, תרחיש מימוש בתוך `tools/native_animations.py`, ו־`% ANIM: ...` לפני השקף; התהליך יעצור אם המזהים לא תואמים. כרגע כל `\visualframe` חייב להישאר שורה אחת, ושקף Beamer חייב לייצר עמוד PDF אחד; אם תשמש באנימציות Beamer מסוג `\pause` שמייצרות מספר עמודים, יש להתאים את מיפוי השקפים לפני בנייה.

**הבחנה חשובה:** שינוי בנוסחה ב־Beamer לא משנה אוטומטית את המשוואה החישובית בתוך אנימציית Python אחרת. כשמשנים את המודל המתמטי, יש לשנות גם את התרחיש המתאים ב־`tools/native_animations.py` או להגדיר משתנים משותפים. המערכת מסנכרנת את תהליך היצירה והקבצים, לא מסיקה בעצמה את הנוסחאות הנכונות.

### ומה לגבי Manim?

קוד המקור של 12 סצנות Manim נשמר ב־`manim/laplace_scenes.py`. כדי לשמור על הסימונים המדויקים שהוספנו בסרטונים 21, 23, 27 ו־29, תהליך ההצגה הראשי משתמש כרגע ב־**אנימציות Python/Pillow מקוריות**, בעלות כיתובים מוטמעים, ולא ברינדור Manim. ניתן לשנות לכל אנימציה את `engine` מ־`native` ל־`manim` ולהוסיף `scene` (שם מחלקת הסצנה); לשם כך חייבים להתקין Manim במכונת הבנייה ולהגדיר גם את ה־GitHub workflow עם חבילת Manim. סצנות Manim המקוריות אינן כוללות בהכרח את המקראים החדשים, ולכן לא מומלץ להחליף אותן בלי בדיקה.

## אוטומציה באמצעות GitHub Actions

בתיקייה `.github/workflows/build.yml` יש workflow מוכן, שמופעל בכל **Push לענף `main` או `master`** וגם בלחיצה ידנית דרך **Actions → Build Laplace seminar → Run workflow**.

1. צור Repository ב־GitHub.
2. העלה אליו את תוכן הפרויקט, **כולל תיקיית `.github` הנסתרת**. הדרך האמינה ביותר היא חילוץ ה־ZIP והעלאת הקבצים באמצעות Git או GitHub Desktop, ולא העלאת ZIP כקובץ יחיד.
3. לאחר Push, פתח את **Actions** וחכה לסיום `Build Laplace seminar`.
4. פתח את הריצה האחרונה והורד את Artifact בשם **`laplace-seminar-ready`**. בתוכו המצגת המעודכנת: `index.html`, `presentation.pdf` ו־`viewer/`.

### פרסום HTML באינטרנט (אופציונלי)

אם תרצה **קישור קבוע למצגת שמתעדכן בכל Push**: ב־GitHub פתח `Settings → Pages` ובחר `Build and deployment → GitHub Actions`, וב־`Settings → Secrets and variables → Actions → Variables` צור משתנה `ENABLE_PAGES` שערכו `true`. ב־Push הבא לענף `main`, נוסף על ה־Artifact, המערכת תפרסם את `dist/index.html` עם האנימציות ב־GitHub Pages. שים לב: בריפו ציבורי גם אתר Pages ציבורי; אין לכלול בו מידע פרטי.

**אזהרת סנכרון:** שמירה ב־Overleaf לבדה **לא** מפעילה GitHub Actions. צריך שהשינויים יגיעו לריפו דרך Push. אם יש לך ב־Overleaf חיבור GitHub Sync, השתמש בלחצן הסנכרון שלו. אם אין — הורד ZIP מעודכן מ־Overleaf והעבר את השינויים לריפו, או ערוך ישירות ב־GitHub. Overleaf ממשיך לקמפל את ה־PDF שלו בזמן אמת; ה־HTML מתחדש רק אחרי Push.

במחשב מקומי ניתן להריץ `python build_all.py` בלי GitHub. GitHub Actions לא מצריך להשאיר מחשב דולק, כל עוד הקוד מגיע ל־GitHub.

## חשוב לגבי פרויקט Overleaf

- אפשר **לייבא את הפרויקט המעודכן ל־Overleaf** ולערוך בו את `main.tex` ולהשתמש ב־XeLaTeX.
- בתוך Overleaf עצמו **לא ירוצו סקריפטי Python/ffmpeg/Manim**, וגם הקובץ `dist/index.html` לא יתעדכן משמירה ב־Overleaf לבדה.
- בתהליך המקומי או ב־GitHub Actions, כל השלבים מתקשרים אוטומטית והפלט נבנה מחדש.

## פיתוח ובדיקות

הפרויקט כולל `tests/test_build.py` כדי לוודא שמזהי האנימציות ייחודיים, קיימים במבנה Beamer, ושאין שכבת מקראי HTML חיצונית. `build_all.py` בודק גם את מספר דפי ה־PDF מול מספר השקפים. מומלץ לבדוק את `dist/index.html` ב־Chrome במחשב שממנו תציג, ולשמור PDF כגיבוי.
